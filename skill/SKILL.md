# skill-inventory — 過去案件の安全な棚卸し

このスキルは3つを対話で進める。**各所で人間の承認を必ず取る。**

1. **NDA/契約読解 → 判定**：契約が唯一の根拠。帰属・複製可否・匿名化要否を判定し台帳に下書き
2. **技術メタデータ集計**：依存ゼロのスキャナで言語比率・FW・規模・期間を JSON 化（スキル集計システム供給用）
3. **掲載用コード生成**：判定が `anonymize`/`as_is` の案件だけ、載せてよい形のコードを生成

リポジトリ本体（このスキルの clone 先）を `$INV` と呼ぶ。`ledger/projects.yaml` が判定の真実。

## 大原則（絶対に破らない）

- **顧客帰属のコードを丸ごと GitHub に置かない。** メタデータのみ、または匿名化後のみ。
- **判定の根拠は NDA/契約。** コードの中身や remote 組織から「推測」で確定しない（remote 組織は補助シグナルまで）。
- **`decision` が未確定（pending）の案件は、コードに一切触れない。** メタデータJSONだけ出す（scanner が fail-safe になっている）。
- **人間承認が空の案件では掲載用コードを生成しない。** `approved_by` が埋まって初めて生成可。

## フロー

### Step 0. 対象を決める
ユーザーに「どの案件を棚卸しするか」を確認。台帳 `ledger/projects.yaml` の `projects[].key` から選ぶ。
台帳に無い案件なら、まず `key / repos / client / remote_org_hint` を追記する（decision は pending のまま）。

### Step 1. NDA/契約を読解して判定を下書き
1. `nda/<key>/` に契約書/NDA原本があるか確認（原本は gitignore 済み。無ければユーザーに配置を依頼）。
2. 原本を読み、次を抽出して**根拠となる条項を引用しながら**要約する：
   - **著作権・成果物の帰属**（顧客か、自社か、共有か）
   - **複製・保存の制限**（第三者環境・個人環境への複製可否、バックアップ条項）
   - **秘密情報の定義と範囲**（顧客名・実データ・社内固有ロジックの扱い）
   - **存続期間**（契約終了後も残る守秘義務か）
3. 上記から `decision` を提案する：

   | 帰属/制限の読み取り | 提案する decision |
   |---|---|
   | 顧客帰属 or 複製明確禁止 | `metadata_only` |
   | 顧客帰属だが匿名化・秘匿除去なら知見公開可 | `anonymize` |
   | 自社帰属 / 制約なし | `as_is` |
   | 判断がつかない・原本が無い | `pending`（据え置き） |

4. **判定は下書き。** ユーザーに「この読み取りと decision で良いか」を提示し、承認を取る。
   承認後、`ledger/projects.yaml` の該当案件を更新：
   `decision`、`nda_reviewed: true`、`approved_by: <承認者>`、根拠を `notes` に短く残す。

> remote 組織はヒント：remote の org が顧客の組織なら顧客帰属を疑い、
> 自分の個人アカウントなら自社帰属を疑う。だが確定は必ず契約の記述で行う。

### Step 2. 技術メタデータを集計（いつでも安全）
```
export SKILL_INV_AUTHOR="<自分のcommit author名 or email>"   # 関与コミット数を出す場合
bash "$INV/scanner/run-all.sh"          # 全案件
# または単体: bash "$INV/scanner/scan.sh" <repo_path> --author "<who>"
```
結果は `output/reports/<key>.json`（言語比率・manifest・framework・git集計・規模）。
**この JSON はコード実体を含まない**ので、どの decision でも生成してよい。スキル集計システムにはこれを供給する。

### Step 3. 掲載用コードを生成（anonymize / as_is のみ）
台帳の `decision` を確認し、分岐する：

- **`as_is`**（自社帰属）：対象リポを `output/publishable/<key>/` にコピー（またはそのまま個人 GitHub private へ）。
  ただしコピー前に **秘匿スキャン**（下記）を必ず通し、鍵・接続文字列・実データが無いか確認。
- **`anonymize`**（顧客帰属だが知見公開可）：
  1. 公開したい範囲を**限定**（顧客固有ロジックの塊ではなく、再利用可能なパターン/ユーティリティに絞る）。
  2. 次を除去・置換する：
     - 顧客名・サービス名・固有名詞 → 汎用名にリネーム
     - API キー・接続文字列・エンドポイント・実データ → 削除 or ダミー化
     - 顧客固有の業務ルール → 一般化 or 削除
  3. 変換後を `output/publishable/<key>/` に置き、**元コードとの差分を人間がレビュー**してから採用。
- **`metadata_only` / `pending`**：コードは生成しない。Step 2 の JSON のみ。

#### 秘匿スキャン（生成前に必ず）
`output/publishable/` に置く前に、少なくとも次を grep で確認する：
```
grep -rEi '(api[_-]?key|secret|password|token|BEGIN [A-Z ]*PRIVATE KEY|postgres://|mysql://|mongodb(\+srv)?://)' <対象>
```
1件でもヒットしたら、ユーザーに提示し、除去してから進む。

### Step 4. 掲載（人間が実行）
- `output/publishable/<key>/` を個人 GitHub private リポへ置くのは**人間の最終操作**。
  `.gitignore` により publishable 配下はデフォルト無視なので、載せると決めたものだけ `git add -f` する。
- 顧客帰属コードをバックアップしたい場合は GitHub ではなく**暗号化ローカルバックアップ**を案内する
  （契約の「第三者環境への複製」に触れないため）。

## スキル集計システム連携
`output/reports/*.json` をスキル集計システムに取り込めば、案件横断の言語比率・FW経験・期間・規模が集計できる。
職務経歴書の技術欄はこの JSON を根拠にする（コードを外に出さずに「何をどれだけやったか」が出る）。

## 別PCでの利用
このリポを clone し `ln -s "$PWD/skill" ~/.claude/skills/skill-inventory`。
別PC上のリポも台帳に `repos:` パスを足せば同じフローで棚卸しできる。
